NIR/ICG Overlay, Monochromatic, or Intensity Map Is Unavailable

Asset Type

Endoscopic / OR Camera System

Manufacturer

Karl Storz

Model

IMAGE1 S Rubina

What This Guide Helps With

Helps isolate unavailable Rubina visualization modes caused by connection, compatibility, light-source, camera, control, or approved configuration problems.

Step-by-Step Troubleshooting

1. Protect the Patient and Maintain Appropriate Visualization

Do not continue a procedure dependent on NIR/ICG visualization when the required mode is unavailable or unreliable. Notify the clinical team and use an appropriate verified alternate imaging method or system.

Do not administer or repeat contrast-related clinical actions solely to test equipment.

Expected outcome: The procedure has a safe visualization plan independent of the affected system.

2. Confirm the Exact Missing Visualization Mode

Determine whether overlay, monochromatic, intensity map, or all NIR-related modes are unavailable.

Confirm whether normal white-light video remains functional and whether the mode was previously available with the same equipment combination.

Expected outcome: The failure is narrowed to a specific visualization function rather than a general video failure.

If the requested mode becomes available and functions normally, troubleshooting can stop after verification.

3. Verify Camera and Rubina-Capable Components Are Recognized

Confirm that the compatible camera head, controller modules, and Rubina light source are powered and recognized.

Inspect external connections for looseness, damage, contamination, or incomplete seating.

Expected outcome: All required external imaging components are connected, recognized, and operating normally.

If correcting a loose connection restores the visualization mode, proceed to final verification.

4. Verify Light-Source Operation

Confirm that the Rubina light source powers normally and is communicating with the imaging system. Check the light cable and accessible connections for proper seating and damage.

Do not look directly into an active light output.

Expected outcome: The light source is operational, connected, and available to the camera system without persistent communication problems.

If normal light-source operation restores NIR modes, troubleshooting can stop after functional verification.

5. Check Scope, Light Cable, and Optical Path

Inspect the telescope, coupler, and light cable for contamination, damage, poor seating, or incompatible components.

Verify that the optical path is assembled correctly and that the image is clear in standard visualization.

Expected outcome: The external optical path is properly connected and produces a clear conventional image.

If correcting the optical path restores the unavailable mode, perform final verification.

6. Check User-Accessible Mode Selection

Using normal system controls, verify that the intended visualization mode can be selected and that camera-head controls have not been assigned differently than expected.

Do not alter restricted configuration or service parameters.

Expected outcome: The required Rubina visualization mode can be selected through normal controls.

If the mode was unavailable because of an approved control or configuration selection, confirm normal operation and stop.

7. Compare With a Known-Good Compatible Setup

When available, substitute a known-good compatible camera head, scope, light cable, or other external component one item at a time.

Maintain the same approved mode settings during comparison.

Expected outcome: The substitution identifies whether the unavailable mode follows a specific external component.

If a defective external component is isolated, remove it from service and replace it with a verified component.

8. Perform Final Functional Verification

Confirm standard white-light imaging and each required Rubina visualization mode used by the department. Verify stable mode switching and consistent video output.

Expected outcome: Required visualization modes are available, stable, and selectable without communication loss.

If all required functions pass, the system may be returned to service according to facility policy.

If the Problem Persists

External connections, compatible accessories, optical components, light-source operation, and normal control selections have been checked.

Remove the affected system from service, label it Out of Service, and send it for repair or bench evaluation. Persistent loss of Rubina modes may involve internal communication, firmware, camera processing, light-source control, or system configuration requiring qualified service.

Evaluate the system using appropriate Karl Storz documentation and approved test equipment. Do not perform unauthorized configuration changes or internal board-level troubleshooting.

Return the system to service only after all required visualization modes have been functionally verified.

Clinical Use Tip

If the surgical plan depends on NIR/ICG visualization, confirm the required Rubina modes before patient use rather than discovering the loss during the procedure.

Work Order Documentation (CCR Method)

CCR = Complaint, Cause, Resolution

Complaint

What was reported by the clinical staff.

Example:
"OR staff reported that standard video was present but the Rubina overlay visualization mode could not be selected."

Cause

What was observed during troubleshooting.

Example:
"Clinical Engineering found an external Rubina system connection was not fully seated, preventing normal communication between components."

Resolution

What action was taken.

Example:
"The connection was reseated, required visualization modes were verified for stable operation, and the system was returned to service."

Helpful Details to Include (If Known)

  • Which visualization mode was unavailable
  • Whether white-light imaging remained normal
  • Camera-head recognition status
  • Light-source status
  • Scope and light-cable condition
  • External connections inspected
  • Known-good components tested
  • Control or configuration observations
  • Modes verified after correction
  • Final device status

Final Thought

Maintain safe visualization first, then verify the complete external imaging path before assuming an internal Rubina processing failure. Escalate persistent mode problems appropriately and document both the fault and final verification.

That is successful troubleshooting.
